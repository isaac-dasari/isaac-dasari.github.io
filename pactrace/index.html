Runtime evidence consistency

Correct facts can still produce the wrong answer.

PacTrace checks provenance, version lineage, freshness and repeatability before an agent or application combines evidence from independently refreshed systems.

The operational gap

Tool success is not evidence consistency.

An Iceberg query can succeed. Search can return results. An API can answer in 80 ms. None of that proves the observations describe the same underlying state.

PacTrace is designed for the interval between “the tools returned data” and “the application is allowed to reason over it.”

Where this matters

Use cases driven by state drift, not by model choice.

PacTrace sits below the model and above independently refreshed data systems. The same failure mode appears in incident response, RAG, risk systems and analytics copilots.

Incident response

Do not correlate current telemetry with an older incident index without knowing it.

An investigation service reads current event data from a lakehouse, searches an incident index and checks a live provider API. PacTrace verifies that the search derivation is compatible with the source state required by the incident policy.

Outcome: use the index when it is current; trigger a bounded reconciliation path when it is not.

RAG and support

Know when retrieval is behind the documents it claims to represent.

A vector or keyword index can be healthy while its source documents have already changed. PacTrace treats the index as derived evidence and compares its recorded source version with independently observed source state.

Outcome: prevent an answer from being presented as current when retrieval is known to lag.

Fraud and risk

Make feature freshness an enforceable contract instead of a dashboard note.

A decision may combine a transaction table, materialized features, device intelligence and a live external signal. Each source can carry a different version or freshness guarantee.

Outcome: reject or disclose evidence that violates the risk workflow’s freshness and repeatability requirements.

Analytics copilots

Separate semantic correctness from state correctness.

A semantic layer can define what “revenue” means. PacTrace answers a different question: whether the observations used to compute or explain revenue are compatible enough to reason over together right now.

Outcome: semantic layers define meaning; PacTrace validates observational coherence.

Architecture

Policy stays readable. Data-heavy reconciliation gets its own execution boundary.

The Python control plane owns source semantics, consistency contracts, adapter plugins and decisions. The Rust data plane receives a domain-neutral Arrow stream for bounded indexed-versus-current reconciliation.

The service boundary is intentionally narrow. Rust does not become another search engine or distributed query engine, and source adapters remain responsible for efficient change discovery.

Execution path

A small number of explicit decisions.

Collect evidence

Adapters normalize source-native semantics such as snapshot lineage, observation time and repeatability.

Evaluate a contract

The caller defines what is acceptable for this task rather than relying on one global freshness rule.

Reconcile when needed

For bounded stale-index scenarios, the Rust data plane compares indexed and current state over Arrow IPC.

Return an explicit decision

Accept, accept with disclosure, require fallback, or reject. Uncertainty is not silently converted into certainty.

Clear boundaries

PacTrace does not try to own every data reliability problem.

The project is strongest when it stays focused on runtime evidence-state compatibility.

Implemented, not illustrated

The reference path uses real storage, search and a cross-language runtime.

The repository includes a PyIceberg source, an independent SQLite FTS5 index, controlled source/index drift, consistency evaluation, a Rust Arrow reconciliation service, container builds and Python-to-Rust integration tests.

Real drift

Source advances while search stays behind.

The reference scenario builds search from one Iceberg snapshot, advances the source without refreshing search, and verifies that stale search cannot see the new record.

Two planes

Python calls Rust over versioned Arrow IPC.

The service validates protocol and schema versions, reconciles bounded state and returns generic row identities with index/delta provenance.

Day-one scope

What the project is built to do now

  • Represent source versions, derivations, freshness and repeatability explicitly.
  • Evaluate task-specific consistency contracts.
  • Detect known source/index drift rather than trusting derived systems to declare themselves current.
  • Run bounded indexed/current reconciliation through a domain-neutral Rust service.

Not claimed

What PacTrace is not

  • Not a global distributed transaction protocol.
  • Not a semantic layer, lineage catalog or observability replacement.
  • Not a distributed SQL engine or search engine.
  • Not a claim that every future connector is already production-hardened.
